## 1) تشغيل المشروع

```bash
npm install          # أول مرة بس
npm run dev          # تشغيل للتطوير → http://localhost:5173
npm run build        # نسخة الرفع (فولدر dist)
npm run db:build     # يجمع ملفات database/schema و يولّد ملفات البيانات من src/data
```

| الرابط | إيه |
|---|---|
| `http://localhost:5173/` | الموقع |
| `http://localhost:5173/admin` | لوحة التحكم — كلمة المرور الافتراضية **admin123** |

التقنيات: React 19 + Vite + React Router + Tailwind (CDN) + lucide-react. قاعدة البيانات: Supabase (PostgreSQL).

## 4) الميزات بالتفصيل

### تتبع الشحنة
- بعد الطلب العميل بياخد **رقم طلب** وزرار "تتبع شحنتك".
- في `/track` بيكتب رقم الطلب + رقم الموبايل (الاتنين لازم يتطابقوا — عشان محدش يشوف طلب حد تاني).
- بيشوف: شريط خطوات (استلام ← تأكيد ← تجهيز ← شحن ← خرج للتوصيل ← تم التسليم)، شركة الشحن ورقم البوليصة ورابط التتبع عند الشركة، حالة العربون والمبلغ المطلوب عند الاستلام، وسجل كل التحديثات بالتاريخ.
- الأدمن بيحدّث من صفحة الطلب: الحالة + ملاحظة (مثال: "وصلت مخزن طنطا") → بتظهر للعميل فوراً.
- لو شركة الشحن مربوطة بـ Webhook التحديثات بتيجي أوتوماتيك (قسم 8).

### العربون
- من **الإعدادات ← الدفع والعربون**: تفعيل، نوعه (نسبة % أو مبلغ ثابت)، القيمة، الحد الأدنى للطلب، والرسالة.
- بيتطلب في **الدفع عند الاستلام** بس. العميل بيشوف المبلغ ورقم المحفظة/إنستا باي (زرار نسخ)، ويكتب الرقم اللي حوّل منه.
- الأدمن بيأكد الاستلام من صفحة الطلب ← الطلب بيتحول "مؤكد" تلقائياً، والمطلوب عند الاستلام بيتحسب = الإجمالي − العربون.
- الافتراضي: 10% للطلبات من 2000 ج.م.

### العروض اليومية وعروض الجمعة
- من **العروض ← جدول العروض**: كل عرض ليه منتجات، خصم إضافي %، شارة، ومواعيد:
  - **كل يوم** — مثال: "صفقة اليوم".
  - **أيام محددة كل أسبوع** — مثال: "سبت المطبخ"، "ثلاثاء المفروشات"، و**"صفقات يوم الجمعة"**.
  - **من تاريخ لتاريخ** — مثال: عروض رمضان / الجمعة البيضاء.
- العرض بيبدأ 12 بالليل وبيخلص آخر اليوم (بتوقيت الجهاز في الموقع، وبتوقيت القاهرة في قاعدة البيانات).
- السعر بيتغير أوتوماتيك في كل مكان (الكارت، صفحة المنتج، السلة)، والمنتج بياخد شارة العرض وعداد.
- صفحة `/friday-offers` بتعرض أي عرض أسبوعي فيه يوم الجمعة: يوم الجمعة "المهرجان شغال"، وباقي الأسبوع "بيبدأ خلال" بعداد.

### إعدادات المظهر (من غير ما تلمس كود)
- **الوضع الغامق والفاتح**: الموقع كله ولوحة التحكم بيشتغلوا بالوضعين. الزائر بيبدّل من زرار الشمس/القمر في الهيدر واختياره بيتحفظ. الأدمن بيحدد الوضع الافتراضي للزوار الجدد (غامق / فاتح / حسب جهاز الزائر). الغامق هو نفس ألوان الموقع الأصلية بالظبط.
- **الألوان**: 3 ألوان هوية (الأساسي، المرور، التدرج) نفسها في الوضعين + 3 خلفيات لكل وضع (الموقع، الكروت، الأقسام) + 5 ثيمات جاهزة فيها الوضعين. الافتراضي = ألوان الموقع الأصلية.
- التقنية: ألوان النصوص متغيرات (`text-ink`, `text-muted`, `text-faint`…) والخلفيات (`bg-base`, `bg-card`, `bg-deep`) بتتقلب تلقائي مع كلاس `dark` — أي صفحة جديدة تستخدمها هتشتغل بالوضعين من غير شغل زيادة.
- **الخطوط**: 10 خطوط عربية (Tajawal الافتراضي، Cairo، Almarai، IBM Plex…) — خط للنصوص وخط للعناوين.
- **التخطيط**: ترتيب وإخفاء أقسام الرئيسية، عرض الصفحة، عدد أعمدة المنتجات، الشريط العلوي، تثبيت الهيدر، أزرار الواتساب، الاشتراك، **وضع الصيانة**.
- **الهوية**: صورة اللوجو وأيقونة التاب (Favicon).
- **SEO**: العنوان، الوصف، الكلمات المفتاحية، صورة المشاركة، منع/سماح الأرشفة، Google Analytics، Facebook Pixel، CSS مخصص + معاينة في جوجل.
- التقنية: الألوان متغيرات CSS (`--brand`, `--bg`…) بيطبّقها `ThemeManager.jsx`.

## 6) قاعدة البيانات Supabase خطوة بخطوة

> 📗 شرح كل ملف وكل جدول ورسم العلاقات وقائمة "أنا عملت إيه؟" في [database/README.md](../database/README.md).

1. **اعمل مشروع**: [supabase.com](https://supabase.com) ← New project ← اختار منطقة **Frankfurt (eu-central-1)** (الأقرب لمصر).
2. **الجداول**: SQL Editor ← New query ← الصق محتوى `database/schema.sql` ← Run.
3. **البيانات**: query جديدة ← الصق `database/seed.sql` ← Run.
4. **أول أدمن**:
   - Authentication ← Users ← Add user (إيميلك وكلمة سر قوية).
   - SQL Editor:
     ```sql
     insert into public.admins (user_id, email, name, role)
     select id, email, 'صاحب المتجر', 'owner' from auth.users where email = 'you@example.com';
     ```
5. **المفاتيح**: Project Settings ← API ← انسخ `Project URL` و `anon public`:
   - للموقع كله: في ملف `.env` (من `.env.example`) **وفي متغيرات الاستضافة**.
   - أو للتجربة: لوحة التحكم ← الإعدادات ← الربط و API.
6. **ارفع بياناتك**: الإعدادات ← الربط ← دخول الأدمن على Supabase ← "رفع كل البيانات لـ Supabase". كرر الرفع بعد أي تعديل (هيظهرلك تنبيه أصفر لو فيه تعديلات ما اترفعتش).
7. **الدوال (اختياري — للشحن والمخزن)**:
   ```bash
   npm i -g supabase
   supabase login
   supabase link --project-ref YOUR_REF
   supabase functions deploy create-shipment
   supabase functions deploy sync-inventory
   supabase functions deploy shipping-webhook --no-verify-jwt
   supabase secrets set WEBHOOK_SECRET=اختار-كلمة-سر CRON_SECRET=كلمة-سر-تانية
   ```

> ⚠️ **service_role key** ممنوع يتحط في الموقع أو `.env` الموقع — ده بيتحط تلقائي جوه الـ Edge Functions بس.

### الحماية (RLS)
- **الزائر**: يقرا المنتجات المفعّلة، الأقسام، العروض، المحتوى، الإعدادات العامة. يكتب تقييم أو اشتراك. يطلب ويتتبع **عن طريق الدوال بس** (`place_order` / `track_order`) — مايقدرش يقرا جدول الطلبات.
- **الأدمن** (موجود في `admins`): كل الجداول.
- **السري** (`shipping_company_credentials`, `integration_settings`): الأدمن والـ Edge Functions بس.

### الدوال المهمة
| الدالة | بتعمل إيه |
|---|---|
| `place_order(payload)` | بتسجل الطلب وبتحسب **الأسعار والخصم والشحن والعربون من قاعدة البيانات** (مش من المتصفح — عشان محدش يغير السعر)، وبتتأكد من المخزون وبتخصمه |
| `track_order(number, phone)` | بترجع حالة الطلب وسجل التتبع لو الرقمين متطابقين |
| `effective_price(id)` | سعر المنتج النهارده بعد العروض |
| `offer_is_live(offer)` | العرض شغال دلوقتي؟ (بتوقيت القاهرة) |
| `validate_coupon(code)` | التحقق من كوبون من غير ما الأكواد تبقى مكشوفة |
| `is_admin()` | المستخدم الحالي أدمن؟ |

## 8) الربط مع شركات الشحن والمخزن (API)

### شركات الشحن
1. لوحة التحكم ← الشحن ← شركات الشحن ← تعديل الشركة:
   - **رابط التتبع**: مثال Bosta `https://bosta.co/tracking-shipments?shipment-number={tracking}` — العميل بيوصله من صفحة التتبع.
   - **ربط الـ API**: Base URL + API Key (+ Secret / Account ID / Pickup لو الشركة بتطلبهم).
2. ارفع البيانات لـ Supabase (بتتحفظ في جدول سري).
3. من صفحة أي طلب ← "إنشاء شحنة API" ← الدالة `create-shipment` بتبعت بيانات الطلب للشركة وبترجع رقم البوليصة وبتحدث الحالة لـ "تم الشحن".
4. **تحديثات أوتوماتيك**: ادي الشركة رابط الـ Webhook:
   `https://PROJECT.supabase.co/functions/v1/shipping-webhook?company=رقم_الشركة&secret=WEBHOOK_SECRET`
   أي تغيير عندهم (خرج للتوصيل / اتسلم / مرتجع) بيتسجل في سجل التتبع ويظهر للعميل.

الشركات الجاهزة في الكود: **Bosta** (مكتوب)، وأي شركة تانية بتمشي على "API خاص" (`POST /shipments` → `{ trackingNumber }`). لإضافة شركة بشكل مختلف (Aramex / Mylerz / J&T / R2S) زوّد دالة في `providers` جوه `supabase/functions/create-shipment/index.ts` حسب توثيق الشركة.

### المخزن / ERP
1. الإعدادات ← الربط و API ← "API المخزن": النظام، الرابط، الـ API Key، سحب الكميات، إرسال الطلبات.
2. حط `sku` لكل منتج في جدول `products` = كود المنتج في المخزن.
3. "مزامنة الآن" بتشغل `sync-inventory`: بتسحب `GET {baseUrl}/stock` → `[{ sku, stock, price? }]` وبتحدث المنتجات، وبتبعت الطلبات المؤكدة لـ `POST {baseUrl}/orders`.
4. **مزامنة أوتوماتيك كل 30 دقيقة** (Supabase ← Database ← Cron):
   ```sql
   select cron.schedule('sync-inventory', '*/30 * * * *', $$
     select net.http_post(
       url := 'https://PROJECT.supabase.co/functions/v1/sync-inventory',
       headers := jsonb_build_object('x-cron-secret', 'CRON_SECRET', 'Content-Type', 'application/json'),
       body := '{}'::jsonb);
   $$);
   ```
   (فعّل إضافتي `pg_cron` و `pg_net` من Database ← Extensions.)
5. Odoo / Zoho / ERPNext: عدّل `fetchStock` في `supabase/functions/sync-inventory/index.ts` حسب الـ API بتاعهم.

### بوابة الدفع (لما تحب تفعّل الدفع بالفيزا)
Paymob أو Kashier أو Fawry Pay — بتتعمل Edge Function شبه `create-shipment` بتنشئ رابط دفع وترجعه، و Webhook بيأكد الدفع. ماتطلبش بيانات الكارت على الموقع نفسه أبداً.

## 9) السيرفرات والاستضافة المقترحة

**مش محتاج سيرفر خاص.** التركيبة المقترحة:

| الجزء | المقترح | ليه | التكلفة التقريبية |
|---|---|---|---|
| قاعدة البيانات + الدخول + الصور + دوال السيرفر | **Supabase** | PostgreSQL + Auth + Storage + Edge Functions في مكان واحد | مجاني للبداية (500MB قاعدة، 1GB صور) — Pro بـ 25$/شهر لما الموقع يكبر (نسخ احتياطي يومي + من غير توقف) |
| استضافة الموقع | **Cloudflare Pages** أو **Netlify** | مجاني، سريع في مصر، HTTPS تلقائي، مسموح تجاري | مجاني |
| بديل | **Vercel** | سهل جداً | الخطة المجانية لغير التجاري — للمتجر Pro بـ 20$/شهر |
| الدومين | Namecheap / GoDaddy / Cloudflare Registrar | `.com` | ~10–15$/سنة |
| الإيميلات (تأكيد الطلب) | Resend أو SMTP | يربط مع Supabase | مجاني لحد 3000 إيميل/شهر |

**إمتى تحتاج سيرفر VPS (Node.js)؟** لو عندك ربط تقيل مع ERP بيحتاج اتصال دائم، أو شغل خلفي كتير. ساعتها: Hostinger VPS / DigitalOcean / Contabo (5–10$/شهر) مع Node.js + PM2، وقاعدة البيانات تفضل Supabase.

### خطوات الرفع على Cloudflare Pages / Netlify
1. ارفع المشروع على GitHub.
2. Cloudflare Pages / Netlify ← New project ← اختار الـ repo.
3. Build command: `npm run build` — Output: `dist`.
4. Environment variables: `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY`.
5. ملف `public/_redirects` موجود (عشان روابط زي `/track` تشتغل). على Vercel ملف `vercel.json` موجود.

## 10) قائمة قبل الإطلاق

- [ ] غيّر كلمة مرور الأدمن، واستخدم دخول Supabase.
- [ ] حط أرقامك الحقيقية (التليفون، الواتساب، المحفظة، إنستا باي، السوشيال) من الإعدادات ← التواصل.
- [ ] راجع أسعار الشحن للمحافظات وشركة الشحن الافتراضية.
- [ ] راجع إعدادات العربون.
- [ ] شغّل `schema.sql` و `seed.sql`، فعّل الأدمن، ارفع البيانات.
- [ ] حط مفاتيح Supabase في `.env` وفي الاستضافة.
- [ ] اعمل طلب تجربة من موبايل وتتبعه من موبايل تاني.
- [ ] حط عنوان ووصف SEO وصورة المشاركة، وربط Google Analytics.
- [ ] بدّل صور Unsplash بصور منتجاتك (ارفعها على Storage ← images وحط الرابط).

### حدود معروفة
- الموقع React (SPA): جوجل بيقرا العنوان والوصف، بس لو SEO أقوى مطلوب لكل منتج يتنقل لـ Next.js مستقبلاً.
- رفع البيانات من لوحة التحكم بيحدّث ويضيف (مش بيمسح). اللي تمسحه من اللوحة امسحه كمان من Supabase ← Table Editor.
- لوجو الشركات وصور المنتجات المرفوعة من الجهاز بتتخزن جوه البيانات — الأفضل ترفعها على Supabase Storage وتحط الرابط.
